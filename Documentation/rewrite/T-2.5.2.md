#### 2.5.2 Software Interfaces

The apps interface with a Supabase backend and a set of Kotlin and Compose libraries. Each is listed below with the version in use and what the apps rely on it for.

**Table 2-60 — Software Interfaces**

| Software interface | Version / platform | Required interaction |
|---|---|---|
| Supabase Kotlin SDK | 3.1.4 | The client all six apps use to reach the backend: PostgREST for college records, GoTrue for sign-in, Storage for exam-paper PDFs and profile photos, and the admin-only edge functions. |
| PostgreSQL (via Supabase) | Supabase-managed | Stores all administrative, academic, fee, approval, communication, and reporting records; Row-Level Security governs who may read and write each row. |
| Ktor | 3.1.1 | The HTTP engine the Supabase client runs on. |
| Room | 2.6.1 | The on-device database that caches records so the mobile apps work offline and sync when back online. |
| Hilt | 2.52 | Dependency injection that wires repositories and view models in the mobile apps. |
| Kotlin · Jetpack Compose · Compose Multiplatform | 2.1.0 · BOM 2024.12.01 · 1.7.3 | The language and UI toolkits the apps are built with (Compose for the Android apps, Compose Multiplatform for the desktop apps). |
| Android operating system | Android 7.0 (API 24) or later | Runs the three mobile apps and provides device storage, the app lifecycle, and secure internet access. |
| Windows operating system | Windows 10 or later | Runs the three desktop apps and provides native file selection, save location, file opening, printing, and sharing. |
| Email delivery (via GoTrue) | Configured in the Supabase project | Delivers account-verification and password-recovery messages, without needing a separate college email application. |
