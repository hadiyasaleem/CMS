#### 2.3.31 FR-31: View Insights and Reports

**Table 2-52 — Description of FR-31**

| Field | Detail |
|---|---|
| Identifier | FR-31 |
| Title | View Insights and Reports |
| Requirement | An administrator shall be able to view college-wide summaries — session overviews, students at academic risk, and per-exam statistics — while a teacher shall be able to view the same kinds of summary limited to their assigned classes. Filters shall cover department, session, semester, subject, or period where they apply, and no-data and loading states shall be explained clearly. |
| Source | College administration and teaching staff |
| Rationale | Ready-made summaries let staff spot attendance and performance problems without compiling registers by hand. |
| Business Rule | The scope of every summary follows the signed-in user's role and assignments, enforced by the database's row-level rules on the underlying records rather than by extra logic in the app. |
| Dependencies | FR-4, FR-6, FR-10, FR-12, FR-15 |
| Priority | Medium |

> **Change from the earlier report:** four SQL insight views (`at_risk_students`, `session_overview`, `session_attendance_summary`, `exam_stats`) were dropped as unused (`20260905000005_drop_unused_insights_views.sql`). The app now computes the same summaries from the base tables and caches them locally; the admin/teacher tiering comes from Row-Level Security on those base tables, so each user's own reads are already scoped. (Note: the Executive Summary's phrase "built directly on Postgres views" is therefore no longer precise — the tiering is still RLS-driven, but the figures are computed over base tables, not read from dedicated views. Worth adjusting T-FM1 if strict accuracy is wanted.)
