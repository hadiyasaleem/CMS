### 4.3 Code Repository

The whole project lives in one Gradle repository, tracked in Git and hosted on GitHub. `settings.gradle.kts` wires it into nine modules: the three mobile apps and three desktop apps, plus the three they share — `core` (the portable domain, DTOs, direct-PostgREST repositories, and auth), `mobile-shared` (the Android UI kit with Room and Hilt), and `desktop-shared` (the Compose-Desktop UI kit and its repositories). The database itself is versioned alongside the code: the Supabase migrations and edge functions sit under `supabase/`, so a schema change and the app code that depends on it move together in the same commit. Build configuration, tests, the documentation sources, generated diagrams, and the final report are all in the same tree.

Keeping everything in one repository is the point, not an accident of convenience. A change to shared behaviour — a repository method, a DTO field, a migration — shows up immediately in every app that depends on it, rather than drifting out of sync across separate projects.
