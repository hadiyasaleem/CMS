#### 2.5.1 User Interface Requirements

All six apps render through one shared Compose UI kit built on Material 3 — the "Modernist" theme, with a signature accent per app (crimson for admin, gold for teacher, emerald for student). Every screen follows the same patterns: a titled header, five-tab bottom navigation on the mobile apps, data tables for structured records, and consistent loading, empty, error, and offline states, in both light and dark themes.

**Table 2-59 — User Interface Requirements**

| Application | Required interface characteristics |
|---|---|
| Admin Mobile | Portrait-first dashboard with five bottom-nav areas; compact cards for college totals and records; short, touch-friendly forms and confirmation dialogs. |
| Admin Desktop | A wider administrative workspace using card, list, and table layouts, with file, export, and print actions — without changing the role's access rules. |
| Teacher Mobile | Fast access to today's schedule, attendance, exams, marks, and menu actions; class and student controls sized for use during a lesson. |
| Teacher Desktop | Wider attendance, marks, schedule, and student views that keep the same labels, status meanings, validation, and navigation order as the mobile app. |
| Student Mobile | A simple personal home and five main areas — attendance, exams, timetable, and more; forms limited to registration, account linking, and permitted profile edits. |
| Student Desktop | Readable personal academic, fee, and notice views with open, save, and print actions; no access beyond what the student mobile app allows. |
| Common | Every main screen uses the shared title treatment, clear back behaviour, refresh, a notification entry where relevant, consistent status colours, and readable typography, with plain loading, empty, validation, and error messages — in light and dark themes, with touch targets of at least 48 dp and content descriptions on icon-only controls. |
