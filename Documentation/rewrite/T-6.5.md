### 6.5 Summary

Because there is no old database to move from, this chapter treated conversion as a fresh rollout rather than a cutover. It starts with a pilot in one department and expands in phases (§6.1), keeping the first group small enough to support and correct while everyone learns. Deployment brings up the single Supabase backend first, then installs the six Kotlin apps — Android APKs and Windows MSIs built from the shared modules (§6.2). The database schema is laid down by the ordered migrations with checked reference data entered through the apps and rosters imported from CSV/XLSX, all under Row-Level Security (§6.2.1). Training is task-first, built around the flows people actually use — recording attendance and generating the three-copy fee challan (§6.2.2) — and the deployed system is then accepted through manual pass/fail checks on the workflows that matter, signed off at the pilot (§6.3). The real difficulties were named rather than glossed: keeping six apps consistent, getting Row-Level Security right, reconciling offline sync without losing or duplicating data, and moving users onto a digital process for the first time (§6.4).
