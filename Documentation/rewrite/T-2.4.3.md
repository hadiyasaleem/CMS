#### 2.4.3 Performance

Performance is stated as targets for a single-college data volume on a stable connection. The measured local baseline is reported in Chapter 5 (§5.4); behaviour under live-network delay and concurrent use is left to acceptance testing rather than asserted here.

**Table 2-57 — Performance Requirements**

| ID | Requirement | Applications | Priority |
|---|---|---|---|
| NFR-P1 | On a stable connection, the first load of a normal list or summary completes within five seconds at single-college data volumes. | All six | High |
| NFR-P2 | A screen that already holds valid cached data shows it within two seconds while it checks for updates in the background. | All six | Medium |
| NFR-P3 | After a teacher selects a class, its attendance roster is ready to mark within three seconds under stable conditions. | Teacher Mobile, Teacher Desktop | High |
| NFR-P4 | The admin start-up data load begins as soon as the role is resolved and never blocks the dashboard from showing progress or the summaries already available. | Admin Mobile, Admin Desktop | High |
| NFR-P5 | Any operation taking longer than one second shows visible progress and blocks accidental duplicate submission while it runs. | All six | High |
