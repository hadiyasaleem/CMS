#### 2.4.2 Usability

All six apps are built from one shared component library — the "Modernist" design system on Material 3 — which is what keeps navigation, wording, and behaviour consistent across roles and platforms.

**Table 2-56 — Usability Requirements**

| ID | Requirement | Applications | Priority |
|---|---|---|---|
| NFR-U1 | A user can reach any primary destination for their role within three selections from the role's home. | All six | High |
| NFR-U2 | Required fields, invalid values, and unavailable actions are explained in plain language beside the form or control, before the user is asked to redo the whole task. | All six | High |
| NFR-U3 | A destructive or high-impact action names the affected record and asks for confirmation first. | Admin and Teacher apps | High |
| NFR-U4 | On mobile, controls for primary actions give a touch target of at least 48 × 48 dp wherever the screen allows. | Three mobile apps | Medium |
| NFR-U5 | The mobile and desktop version of a role use the same labels, the same order of major destinations, the same status meanings, and the same form rules. | All six | High |
| NFR-U6 | Every main screen has a clear title, predictable back behaviour, a way to refresh, loading feedback, and an understandable empty or error state. | All six | High |
| NFR-U7 | Body text meets at least 4.5:1 contrast, icon-only controls carry content descriptions, status is never conveyed by colour alone, the layout respects the system font scale, and a dark theme is available. | All six | Medium |
