### 7.2 Traceability Matrix

Every functional requirement is traced here to where it is designed, where it lives in the code, and how it was checked. The code column names a representative artifact — a table, a controller, an edge function, or a shared UI component — rather than every file that touches the feature; it is there to show the requirement is real in the codebase, not to walk through the implementation. The test column is honest about method: some requirements have an automated test ID (the sync engine, UT-1..3; the role workflows, FT-1..4; the app↔Supabase seams, IT-1..3), and the rest were verified as manual scenario checks against controlled data. Two requirements, FR-25 and FR-26, are kept in the matrix for continuity but marked withdrawn — the document-publishing/download feature was removed, so there is nothing to deliver or test.
