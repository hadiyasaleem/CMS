#### 3.3.2 Component Structure

The code is organised into layers of components rather than six standalone programs. At the base sits the portable `core` module — the domain model, the data-transfer objects, the repositories, and the authentication logic every app shares. Two platform kits build on it: `mobile-shared`, the Android UI kit with the Room cache and the Hilt wiring the three phone apps use, and `desktop-shared`, the Compose-for-Desktop UI kit the three desktop apps use. The six app modules themselves are thin — each supplies its role's screens and assembles them from those shared parts. So a workspace in any app calls into a shared repository, which applies the identity, academic, publishing, and reporting rules before reaching the Supabase backend; the same rule runs the same way whichever app invoked it.
