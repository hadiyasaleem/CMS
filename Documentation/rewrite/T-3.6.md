### 3.6 Behavioural Model

Behavioural models show how the parts identified in the architecture cooperate over time. The interaction (sequence) diagrams trace the main cross-role journeys — signing in and role routing (§3.6.1), an administrator publishing college information (§3.6.2), a teacher recording attendance and assessment (§3.6.3), and a student registering and linking an account (§3.6.4) — using application-neutral names, so each flow reads the same on the mobile and desktop version of a role. The state diagrams then follow how records change when a decision is made: a student link request (§3.6.6), a mark-correction request (§3.6.7), and publishable information (§3.6.8).

> **Note:** a former §3.6.5 covered a document publication-and-opening flow. The Documents feature was removed, so that subsection is withdrawn; publishing college information (datesheets, notices, calendar events) is covered by §3.6.2.
