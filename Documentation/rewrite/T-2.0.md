## 2. Analysis

Where the last chapter set out what the system is for, this one pins down what it must actually do and the conditions it has to hold to. It begins with the people who use the six applications — the three roles across mobile and desktop — and how their needs become use cases and, from those, concrete requirements. The functional requirements spell out the services each role gets; the non-functional and external-interface requirements set the expectations around them, from reliability, usability, performance, and security to how the apps handle devices and the network. Everything here is written so it can be checked against the finished system later.
