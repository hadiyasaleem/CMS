#### 2.5.4 Communications Interfaces

All communication is between the apps and the Supabase backend; no other external service sits in the loop.

**Table 2-62 — Communications Interfaces**

| Communication | Requirement |
|---|---|
| App ↔ backend | All six apps exchange sign-in, college records, and files with the Supabase backend over an encrypted (HTTPS) connection — PostgREST for data, GoTrue for authentication, and Storage for files, carried over Ktor. An interrupted exchange leaves a retryable state, never a half-completed but confirmed action. |
| Notifications | Notifications are delivered in-app only — there is no push service (no FCM). Each one appears solely in the notification list of the users in its target role or academic audience. |
| Email | Only account-verification and password-recovery messages are sent, through the backend's configured email (GoTrue); the apps send no SMS. Errors are reported without revealing whether another account exists, beyond what the current request needs. |
| File transfer | Uploads (such as an exam-paper PDF) and downloads preserve the file's content and clearly report progress, cancellation, an unsupported type, or failure. |
| Service keep-alive | A scheduled GitHub Actions job pings a lightweight endpoint every few days so the free-tier Supabase project is not paused for inactivity. |
