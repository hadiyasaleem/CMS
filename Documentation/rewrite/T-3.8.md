### 3.8 Summary

This chapter turned the requirements into a full design for the six applications — Admin, Teacher, and Student, each on mobile and desktop. The domain, context, component, layered, and data models set out the structure; the interface views and screen-action tables showed how each role does its work and gets feedback; and the interaction and state-transition diagrams traced the main behaviours — sign-in and role routing, administrative publication, teaching (attendance and marks), student registration and linking, and the approval and publication state machines. The design decisions balance role separation against a single shared rule-set, consistent mobile and desktop behaviour, access enforced in the database, clear academic relationships, offline-first working within connection limits, and familiar device services. These models are the reference for the implementation in Chapter 4.
