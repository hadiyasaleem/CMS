#### 2.4.1 Reliability

The system is offline-first: each app keeps a local cache and syncs only the records that have changed, so most of the reliability requirements are about never losing what a user has already seen or entered.

**Table 2-55 — Reliability Requirements**

| ID | Requirement | Applications | Priority |
|---|---|---|---|
| NFR-R1 | Once the system confirms a record is saved, it stays available after the app is closed and reopened, and is shown from the local cache even with no connection. | All six | High |
| NFR-R2 | A temporary loading or connection failure never closes the app or clears what is already on screen; cached data stays visible and the user is offered a clear retry. | All six | High |
| NFR-R3 | On an administrator's first entry in a session, the core reference data — departments, teachers, students, sessions, requests, and summaries — begins loading automatically, without a screen-by-screen refresh. | Admin Mobile, Admin Desktop | High |
| NFR-R4 | A valid session is restored when the app reopens; an expired or signed-out session returns the user to sign-in without showing any protected data. | All six | High |
| NFR-R5 | Every create, update, upload, approval, or delete is validated on the server; a failed action leaves the previous record unchanged unless the system confirms success. | All six | High |
