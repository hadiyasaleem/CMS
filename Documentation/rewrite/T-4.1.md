### 4.1 Algorithm

The algorithms below cover the work shared across all six apps and the role-specific work that matters most to administrators, teachers, and students. Each is given as language-neutral pseudocode with a rough cost, where **N** is the students in a roster, **P** the timetable periods checked for a conflict, **S** the candidate students in a session, **M** the published records scanned, and **F** the size of a file.

**Table 4-1 — Algorithm Coverage Across the Six Applications**

| # | Algorithm | Primary applications | Main purpose |
|---|---|---|---|
| 1 | Start and route a signed-in user | All six | Restore a valid session and open only the workspace for the account's role. |
| 2 | Prepare administrative data | Admin Mobile, Admin Desktop | Load the core college reference data once for the signed-in administrator. |
| 3 | Validate a timetable period | Admin Mobile, Admin Desktop | Prevent teacher, room, and session clashes before a period is saved. |
| 4 | Record class attendance | Teacher Mobile, Teacher Desktop | Validate and save one complete dated register. |
| 5 | Record assessment marks | Teacher Mobile, Teacher Desktop | Validate first-time scores and lock them once submitted. |
| 6 | Review a mark correction | Teacher and Admin (mobile and desktop) | Route a correction through a visible request and an authorised decision. |
| 7 | Link a student account | Student and Admin (mobile and desktop) | Match a registered account to one approved student record. |
| 8 | Build a student academic overview | Student Mobile, Student Desktop | Combine the student's own attendance, schedule, marks, results, and fees. |
| 9 | Publish information for an audience | All six, according to role | Publish and retrieve notices, datesheets, and calendar events for the permitted audience. |
| 10 | Complete a desktop file action | Admin, Teacher, and Student Desktop | Open, save, export, print, or share an authorised file through the operating system. |
