#### 2.3.17 FR-17: Submit Examination Paper

**Table 2-38 — Description of FR-17**

| Field | Detail |
|---|---|
| Identifier | FR-17 |
| Title | Submit Examination Paper |
| Requirement | For a subject that appears on a published mid-term datesheet, the assigned teacher shall be able to attach an examination-paper PDF to that datesheet slot and submit it, optionally with a short description. The system shall reject a missing file, an unsupported or oversize file (PDFs up to 5 MB), a slot the teacher is not assigned to, and a transfer failure — each with a clear message. Only one active paper is kept per slot; submitting again replaces it. |
| Source | Teaching staff and college administration |
| Rationale | Binding each paper to a published datesheet slot keeps every submission attached to a real, scheduled exam rather than a free-form choice. |
| Business Rule | A teacher may submit only against their own assigned slots on a published mid-term datesheet; the file is stored in the `exam-papers` bucket. Administrators can view and download submitted papers but do not review or approve them. |
| Dependencies | FR-5, FR-8, FR-18 |
| Priority | High |

> **Change from the earlier report:** exam-paper submission was reworked (`20260910130000_exam_paper_rework.sql`). A paper is now tied to a **published datesheet slot** instead of a free (session, subject, exam-type) selection, it applies to **mid-term exams only** (the `exam_type` field was dropped, since datesheets never cover sessional), and the **admin "review/approval" step was removed** (the `review_status`/`reviewed_by`/`reviewed_at`/`teacher_notes` columns and their guard trigger were dropped). Any description of an admin approving or reviewing papers is stale and has been removed.
