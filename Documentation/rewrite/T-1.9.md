### 1.9 Tools and Technologies

All six applications are written in one language on one build, which is what lets them share their logic and their look rather than being six separate projects. The stack is Kotlin throughout, with Jetpack Compose for the Android apps and Compose Multiplatform for the desktop apps, Hilt for dependency wiring, Room for the on-device cache, and a Supabase (PostgreSQL) backend reached through the Supabase Kotlin SDK. Table 1-2 lists the principal tools, their versions, and why each is used.

**Table 1-2 — Tools and Technologies for the Proposed Project**

| Tool / Technology | Version | Rationale |
|---|---|---|
| Kotlin | 2.1.0 | The single language for all six apps and the shared modules, so common logic is written once. |
| Jetpack Compose (BOM) | 2024.12.01 | Declarative UI toolkit for the three Android applications. |
| Compose Multiplatform | 1.7.3 | Builds the three desktop UIs with the same Compose approach, reusing the shared component kit. |
| Hilt | 2.52 | Dependency injection that wires repositories and view models across the apps. |
| Room | 2.6.1 | On-device database that caches records, so each app still shows data offline and syncs when back online. |
| Supabase Kotlin SDK | 3.1.4 | Client for the backend — sign-in (auth/GoTrue), record access (Postgrest), and file storage. |
| PostgreSQL | Supabase-managed | Relational store for every college record; Row-Level Security enforces who may read and write each row. |
| Ktor | 3.1.1 | HTTP engine the Supabase client runs on. |
| Android SDK | compile/target 36, min 24 | Builds and runs the mobile apps; supports Android 7.0 (API 24) and later. |
| JDK | 17 | Build and runtime toolchain for the desktop apps and the shared code. |
| Gradle (with AGP 8.13.2) | 8.13 | Repeatable multi-module build and packaging for all six applications. |
| Git & GitHub | — | Version control and team collaboration. |
