### 3.3 Architectural Design

The system follows a layered client-server design. The six apps present role-specific workspaces on top of shared services that apply the same validation, access rules, and record operations, so the college's rules are written once rather than in six places. The managed backend holds the accounts, the college data, and uploaded files such as exam papers and photos. Each app also keeps a role-scoped local copy of the records it is allowed to see: it builds that copy on first use, and later refreshes pull only what changed since the last successful sync and apply it in one step — enough for a useful view on a weak connection, without becoming a second source of truth, since the online database stays authoritative.
