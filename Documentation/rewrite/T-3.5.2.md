#### 3.5.2 Screen Objects and Actions

The two screens below show how visible objects, user actions, and feedback work together. The same objects appear in the matching mobile and desktop app; only their position changes with the space available.

**3.5.2.1 Use Case: Mark Class Attendance**

**Table 3-5 — Screen Objects and Actions for Mark Class Attendance**

| Screen object | User action | Displayed feedback |
|---|---|---|
| Class and subject selectors | Choose an assigned class meeting and subject. | Only the teacher's own assignments are offered; missing context is explained before the roster opens. |
| Search field | Filter the roster by name or roll number. | The list narrows as the teacher types. |
| Student rows (Present / Absent / Leave segmented control) | Mark each student present, absent, or on leave, and flag a present student as late where needed. | The chosen state shows at once; late is an add-on flag, not a separate status. |
| Status summary strip | — (read-only) | Running present, absent, and leave counts update as marking proceeds. |
| Submit Attendance (sticky action) | Submit the completed register. | An incomplete or duplicate register is flagged; a successful save shows confirmation and the recorded date. |
| Retry (offline) | Retry after an interrupted connection. | Unsaved selections stay on screen, so the class does not have to be marked again. |

**3.5.2.2 Use Case: Review a Mark Correction**

**Table 3-6 — Screen Objects and Actions for Review a Mark Correction**

| Screen object | User action | Displayed feedback |
|---|---|---|
| Pending request row | Open a request and review the student, subject, recorded mark, requested mark, and the teacher's reason. | The original and requested values stay visible side by side, so a decision is never made blind. |
| Approve action | Accept a valid correction (through a confirmation step). | The mark is updated, the request becomes approved, and it leaves the pending list. |
| Reject action | Reject the request, recording a reason where the screen asks for one. | The mark is left unchanged, the request becomes rejected, and the decision is kept. |
| Empty or failure state | Review the queue, or retry loading it. | The screen tells "no pending requests" apart from a connection or permission problem. |
