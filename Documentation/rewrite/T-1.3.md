### 1.3 Objectives of the Proposed System

Each objective below is concrete enough to check against the finished system:

- Ship six working applications — a mobile and a desktop app each for administrators, teachers, and students — all running against the same college database.
- Hold a single authoritative record for every department, academic session, subject, teacher, student, timetable, attendance entry, mark, semester result, and fee structure, so the same value is never entered twice.
- Let an authorised teacher record a full class attendance register on screen instead of on a paper register, and make that register visible to the administration and to the affected students once it syncs.
- Route every change to an already-recorded mark through an administrator's approval, so a submitted score cannot be altered silently.
- Record semester results — including GPA, CGPA, and supply (repeat) subjects — against the enrolled student rather than on a separate sheet.
- Give each student their own attendance, timetable, marks, results, fee challan, fines, datesheets, and notices on their own device, so routine questions no longer require an office visit.
- Publish notices, calendar events, and examination datesheets to the roles they are meant for, on both mobile and desktop.
- Show administrators live summaries of departments, sessions, teachers, students, attendance, and academic performance drawn straight from the records rather than compiled by hand, with a teacher's view scoped to their own classes by the same rules.
- Enforce role-based access throughout, so each user can see and do only what their role allows.
- Keep the mobile and desktop version of each role consistent in content, navigation, and the main workflows.
- Verify all six applications through functional and user-interface testing before final submission.
