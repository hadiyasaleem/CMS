### 5.5 Summary

Testing was aimed where a fault would hurt most: the shared `core` logic that every app runs. Automated unit testing is narrow by design — it covers the incremental-sync engine, where a silent paging or checkpoint error would quietly lose or duplicate records (§5.1). The role workflows — sign-in and routing, attendance, marks with the two-person correction, and student linking — were checked as functional scenarios against controlled sample data (§5.2), and the seams where the apps meet Supabase were exercised at the integration level: Row-Level Security refusing out-of-role access, a write in one app reaching another through sync, and privileged actions running only through edge functions (§5.3). Parity between the mobile and desktop builds is held together by the per-screen scenario registry rather than a second test suite. Performance (§5.4) is reported honestly as an indicative local baseline on development hardware — cached screens open without waiting on the network and a refresh moves only changed rows — not a scale or field measurement. The result is a system whose critical rules are verified, with the limits of that verification stated plainly rather than dressed up.
